# Tess, slice 1: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Tess (chat by text and voice, the Core, the morning brief, Stage mode), an engine with one gate and one step log, three working crew on Tomorrow's Tech AI (Follow-through, Content, Finance), and the floor showing those three from real logged steps.

**Architecture:** A crew "bot" is a row of configuration run by one engine in `src/lib/crew/`. A run is a resumable Claude tool-use loop whose transcript is stored append-only; every tool that changes anything passes through `act()` in `gate.ts`, which decides, executes and writes one `ai_steps` row. Shifts are started by one cron route; chat is a run started from the grand tab. The floor and the grand tab read only `ai_steps`.

**Tech Stack:** Next.js 16 (read `AGENTS.md` and `node_modules/next/dist/docs/` before using a Next API), React 19, Supabase, `@anthropic-ai/sdk` (upgraded in Task 1), `three`, ElevenLabs HTTP API, vitest with `src/test-support/fake-supabase.ts`.

**Spec:** `docs/superpowers/specs/2026-11-20-tess-ai-crew-design.md`. Mockups to port: `.superpowers/brainstorm/724-1795154360/content/grand-tab.html` and `the-floor-v4.html`.

## Global Constraints

- Models: Tess `claude-opus-5-5`; crew `claude-sonnet-5-5`. No date suffixes. Never send `temperature`/`top_p`/`top_k`, `budget_tokens`, a forced `tool_choice`, or `thinking: {type: "disabled"}` to these models. Set `output_config.effort` explicitly (`"medium"` for Tess, `"low"` for crew shifts).
- Before writing any Claude API code, read the `claude-api` skill and its `typescript/claude-api/tool-use.md`, `shared/tool-use-concepts.md` and `shared/prompt-caching.md`. Do not guess SDK names.
- Transcripts are append-only. Append each response's full `content` (thinking blocks included) unchanged; never edit or drop earlier turns.
- Email signature, exactly: `Tess, AI assistant to John Hockinson, Tomorrow's Tech AI`. Crew email is sent with `sendMail` from `src/lib/google/gmail.ts` (John's mailbox), never Resend.
- Starting caps: AI spend $5.00 a day, 5 first-contact emails a day, 2 posts a day per channel. Minimum gap between two emails to the same address: 48 hours.
- Nothing is sent for a business unless its `mode` is `launch`, and `mode` only becomes `launch` when John confirms the playbook.
- Every `act` tool call must carry a goal and an expectation. No goal, no action.
- Never contact an address `loadSuppression` blocks or a lead `emailBlock` blocks. Never state or imply the sender is human.
- "Always John" kinds are written to `ai_actions` and never executed by the crew: money leaving, a price not in the catalog or signing, deleting records, changing access.
- A floor station is shown only if at least one registered tool maps to it.
- Glow: bloom strength at most 0.45, threshold at least 0.5, tone mapping on, no value that jumps in one frame.
- Environment: `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `ANTHROPIC_API_KEY`. Server-side only.
- Every new table: RLS on, admin-select policy via `public.is_admin()`, `revoke all ... from anon`, as in `supabase/migrations/20261119090000_cron_runs.sql`. Migrations are written, not applied.
- Every server action and admin API route checks `getAdminUser()` first, as in `src/app/admin/task-actions.ts`.
- `npx tsc --noEmit -p tsconfig.json`, `npx eslint src` and `npx vitest run` stay clean after every task (CI enforces this).

## Review Focus

1. **A run is cut off mid-loop by the one-minute request limit.** It must resume on the next tick and must not repeat an action it already carried out. (Task 6)
2. **The model asks for a tool that does not exist, or sends input that fails the schema.** The run gets an error `tool_result` and continues; nothing throws. (Task 6)
3. **The lead has no email, or the address is suppressed.** The gate refuses, the refusal is logged as a step the floor can show, and the run carries on with its other work. (Task 3, Task 5)
4. **The daily AI budget runs out mid-shift.** The run stops cleanly as `paused_budget` before the next model call, with no half-sent work. (Task 3, Task 6)
5. **No microphone, speech recognition unsupported, or no ElevenLabs key.** Typing still works, Tess's words still appear as text, and nothing shows an error wall. (Task 10)

### Task 6: The run loop

**Files:** Create `src/lib/crew/run.ts`, `src/lib/crew/roles.ts`. Test `src/lib/crew/__tests__/run.test.ts`.

**Interfaces — Produces:**

```ts
export type ModelCall = (req: { model: string; system: Anthropic.TextBlockParam[]; tools: Anthropic.Tool[]; messages: Anthropic.MessageParam[] }) => Promise<Anthropic.Message>;
export const MAX_STEPS_PER_RUN = 24;
export function advanceRun(sb: SupabaseClient, runId: string, opts: { deadlineAt: number; call?: ModelCall }): Promise<{ status: RunStatus; stepsThisTick: number }>;
export function systemFor(agent: Agent, business: Business, goals: Goal[], rules: Rule[]): Anthropic.TextBlockParam[];   // roles.ts
export const ROLE: Record<AgentSlug, { prompt: string; firstMessage: string }>;                                          // roles.ts
```

`advanceRun` loads the run and its transcript, then loops: stop with `waiting` if `Date.now() >= deadlineAt`; stop with `paused_budget` if today's spend has reached the cap; call the model; append the full response content to the transcript and save it; record usage with `recordAiUsage` under the agent's `crew-*` slug; on `stop_reason: "tool_use"` run each tool call (unknown tool or schema failure becomes a `tool_result` with `is_error: true`), append all results in one user message, save, continue; on `end_turn` finish `done`; on `refusal` finish `failed` with the category; at `MAX_STEPS_PER_RUN` finish `stopped`. The default `call` uses `anthropic().messages.create` with `output_config.effort`, `max_tokens: 16000` and a `cache_control` breakpoint on the last system block. `systemFor` puts the stable role text first and the rules, playbook and goals last. Each role prompt states: who the bot is, its standing job, that every action needs a goal and an expectation, that it speaks as Tess and never as a human, and that it ends by calling `report`.

### Task 7: Shifts and the cron

**Files:** Create `src/lib/crew/shifts.ts`, `src/app/api/cron/crew/route.ts`. Modify `src/lib/cron/names.ts`, `vercel.json`, `src/app/api/cron/followups/route.ts`. Test `src/lib/crew/__tests__/shifts.test.ts`.

**Interfaces — Produces:** `dueAgents(agents: Agent[], runs: Pick<Run, "agent_id" | "status">[], now: number): Agent[]` (pure) and `runShifts(sb, opts: { deadlineAt: number }): Promise<{ advanced: number; started: number }>`.

An agent is due when it has a schedule, is not paused, has no `running` or `waiting` run, and `last_shift_at` is older than its schedule. `runShifts` first advances `waiting` shift runs, then starts due ones, until the deadline (50 seconds).
